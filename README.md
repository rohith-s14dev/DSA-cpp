- Explain the approach, correctness, complexity, and edge cases for each problem.
- Keep readable, compilable solutions with small test cases.

## Problem documentation format
Each problem document aims to include:
1. Problem summary and examples
2. Constraints and edge cases
3. Brute-force idea (when useful)
4. Optimized approach and reasoning
5. C++20 implementation
6. Dry run
7. Time and space complexity
8. Interview follow-up questions

Runnable source files are kept under `solutions/`. Compile an example with:

```bash
g++ -std=c++20 -Wall -Wextra -Wpedantic -O2 solutions/two_sum.cpp -o two_sum
./two_sum
```
